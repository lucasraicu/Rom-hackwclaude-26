# FundProof frontend

Run from the repository root (PowerShell):

```powershell
python -m venv frontend/.venv
frontend/.venv/Scripts/python -m pip install -r frontend/requirements.txt
cd frontend
.venv/Scripts/python -m streamlit run app.py
```

Open http://localhost:8501. Demo Mode is on initially. After clicking Load sample results, all records and embedded references are synthetic fixtures in demo_data.py, not real citations or AI outputs. Uploads are staged in memory; demo loading ignores their contents. Reviews persist across navigation in the current Streamlit session, not across server restarts or browser sessions. Export before leaving. No authentication, database, compliance engine, or backend is implemented.

Demo walkthrough: Overview ? Allocation Review ? select Employee A payroll ? enter missing-hours notes ? save Needs more information ? select produce ? review evidence and acknowledge ? Approve for export ? Export. The report retains unresolved evidence even after a reviewer approves a row.

## Proposed backend contract — requires teammate agreement

No existing backend contract was found. This adapter is an integration proposal, not a claim that an endpoint exists. Set the environment variable in your shell; .env files are not automatically loaded:

```powershell
$env:FUNDPROOF_BACKEND_URL = 'http://localhost:8000'
```

Disable Demo Mode and upload documents. api_client.py POSTs JSON to `/analyze` with a 60-second timeout:

```json
{"documents":[{"kind":"grant","name":"agreement.txt","content_base64":"..."}]}
```

Kinds: grant, expenses, payroll, supporting, evidence_register. Content is base64 original bytes. UI accepts PDF/TXT grants, PDF/PNG/JPG/JPEG receipts and invoices, and CSV transaction, payroll and evidence registers, with a 10 MB per-file limit. Backend must validate actual content, implement parsing and enforce aggregate request limits. Upload staging is not validation of financial records.

Response object:

```json
{
  "funds": [{"name":"Fund name","budget":10000,"restriction":"Source-provided restriction"}],
  "transactions": [{
    "id":"unique-id", "expense":"Description", "amount":125.50,
    "fund":"Fund name", "status":"Needs Review",
    "explanation":"Backend explanation", "restriction":"Relevant source text",
    "evidence":"Evidence supplied by backend",
    "references":["Real document identifier and page or row"],
    "missing":["Missing timesheet"]
  }]
}
```

Statuses are Supported, Needs Review, Unsupported. Fund names and transaction IDs must be unique; amounts and budgets are nonnegative finite numbers. All text fields are strings, references/missing are arrays of strings. Empty evidence/references are displayed as absent. No citations or eligibility decisions are generated by the frontend. Backend errors display a retry message and preserve prior results and reviews. New successful analysis replaces reviews. Reviewer decisions never alter backend recommendations.

Remaining integration: agree endpoint/schema, decide split allocations and unassigned funding representation, connect real document provenance, agree currency/date semantics (demo uses USD, November 2026), add backend persistence and reviewer identity outside this frontend task. Current contract represents one proposed source per expense. Review notes and decisions are exported locally, not sent to backend.

Verification:

```powershell
frontend/.venv/Scripts/python frontend/test_app.py
```

Launch from `frontend/` so Streamlit loads `.streamlit/config.toml`. The dark theme provides consistent contrast for native tables, inputs, menus and charts.

The workspace starts empty. In Upload Documents, click **Load sample results** with Demo Mode enabled. Six fixed mock allocations load without backend access, with a persistent success message and preview. Overview and Allocation Review read the same session data. Existing reviews require replacement confirmation. Uploaded files are not used to produce mock results.

`EXPECTED_TEST_CASES_DO_NOT_UPLOAD.txt` is blocked by filename in both upload staging and the API client before content is read or transmitted. No demo directory is scanned or submitted automatically. The local checkout did not contain `demo/` at implementation time; existing frontend synthetic fixtures are used without inventing references to missing files. New upload kinds remain part of the proposed backend contract.

The sixth uploader, Other Supporting Documents, accepts multiple PDF, TXT, CSV, DOCX, XLSX, PNG and JPG files. Filenames appear in the staged documents list. These files remain staged only and are excluded from backend requests until backend support is available; analysis requires a document from one of the original five categories. Dashboard charts use explicit USD and expense-count axes.
